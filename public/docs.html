CUSTOMER SEARCH — SMART CACHE
Cache Build Process (first open)
1
Fetch all active jobs
GET /jobs/?Stage=in(Pending,Progress) — up to 250, with Tags & DateModified
2
Deduplicate by Customer.ID
Tracks most-recently-modified job per customer; marks overdue if >30 days since DateModified
3
Batch enrichment (3 at a time)
Fetches Tags + Address per customer; 300ms delay between batches to respect simPRO rate limits
4
Priority tagging
Customers with a tag containing "testing" → marked as Major (up to 10 shown with ★)
5
Cache stored 60 seconds
Bypass with ?force=1; fallback to direct simPRO search + site wildcard search if <10 results
LIVE PRESENCE TRACKING
  • In-memory Map<jobId, Map<userName, {lastSeen, color}>>
  • POST /api/presence/heartbeat — called every ~10s while job is open
  • Viewer removed if no heartbeat for 15 seconds
  • Cleanup runs every 5 seconds via setInterval
  • Colors assigned deterministically via name hash → 8-color palette
  • Multiple users can view same job simultaneously
JOB DETAIL VIEW
Aggregated by fetchFpowData(jobId)
  • Job metadata: ID, name, stage, customer, site
  • Site address: suburb, state, postcode (AU only; hides overseas)
  • Service dates: 6-Monthly and 12-Monthly next-service via ServiceLevels
  • Outstanding works: equipment type + issue description per defect
  • Description cleaning: strips 30+ Redmen boilerplate patterns (techs attending, phone, address, standard scope text, AS/NZ references)
  • Limited to first 15 meaningful lines for display
EMAIL CALL SHEET
  • POST /api/send-email — rate limited: 5 per 15 min
  • To: recipient email, CC: managerEmail or MANAGER_EMAIL env var
  • Subject: "FPOWS Call Sheet - Job #ID - Client Name"
  • Attaches logo.png (if present) via CID embedding
  • Sent via SMTP with 1-retry fallback (2s delay)
  • Success logged to email_history.jsonl as structured JSON
JOB HISTORY MODAL
  • GET /api/customers/:id/jobs — last 30 jobs ordered by -ID
  • Filtered to: Pending, Progress, Completed, Invoiced stages
  • Sorted: In Progress → Pending → Completed → Invoiced, then by job ID desc
ADMIN PANEL
  • Log viewer: GET /api/logs — last 50 entries from email_history.jsonl (reversed)
  • Delete entry: POST /api/delete-history — removes by timestamp match
  • Manual report: GET /api/trigger-manager-report — runs portfolio report on demand
  • All three require x-admin-key header or ?key= param
  • Key injected into UI via window.FPOWS_KEY at page load

Data Flows
4 / 5
ASSET SYNC FLOW (syncAssetDates)
1
Trigger — siteId + jobDate + jobType received
Called after a job is processed; jobType is "6 Monthly" or "12 Monthly"
2
Calculate next service date
6 Monthly → baseDate + 6 months · 12 Monthly → baseDate + 1 year · Formatted as YYYY-MM-DD
3
Fetch customer assets for site
GET /customerAssets/?Site.ID={siteId}&pageSize=250 — includes inline ServiceLevels
4
Match service levels by name
12 Monthly matches: "annual", "12 month", "yearly", "12month"
6 Monthly matches: "6 month", "bi-annual", "half year", "semi-annual"
5
PATCH only if date changed
Compares existing ServiceDate / NextDate — skips PATCH if already correct; writes {ServiceDate, NextDate} per matching service level
EMAIL CALL SHEET FLOW
1
UI builds HTML email body
Job detail, cleaned description, service dates, outstanding works — passed as htmlContent in POST body
2
Server sends via Gmail SMTP
To: recipient · CC: managerEmail or MANAGER_EMAIL · CID-attached logo.png · 1 retry on failure
3
Log structured entry to email_history.jsonl
Fields: timestamp, type, jobId, client, clientEmail, managerEmail, subject, siteId, siteName
DAILY PORTFOLIO REPORT (sendManagerDailyReport)
Triggered: 06:00 Asia/Manila daily · or manually via /api/trigger-manager-report
1
Read email_history.jsonl
Exit early if file is missing or empty
2
Discover active portfolio sites
Fetches all Pending/Progress jobs (up to 250) — builds Map of unique Site IDs with representative job IDs
3
Safety catch — today's schedules
Fetches /schedules/?Date=today and merges any new site IDs not already discovered
4
Merge email history sites
Adds any siteId from logs not in discovered set; for logs with only jobId, fetches site via job lookup
5
Fetch live data per site (staggered)
Calls fetchFpowData(representativeJobId) for each site — 800ms pause between each to respect API limits
6
Build & send HTML report email
One row per site: site name, site ID, 6/12 monthly service dates, outstanding works table · Sent to MANAGER_EMAIL · Status written to last_daily_report.txt
